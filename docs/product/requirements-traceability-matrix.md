## Reading the matrix

The forward indexes use the approved decision and feature catalogs as denominators. The requirement index can be read in reverse from every verification artifact via linked IDs. Features can have later-release extensions without changing their initial release. Requirement and acceptance rows use the release of the behavior being verified. A feature index may point to a later capability without making it part of an earlier release gate. Requirement links resolve to their verification methods in the SRS. Approved feature coverage measures the existence of linked requirements and acceptance criteria. Actual verification evidence remains pending implementation.

### Pending traceability gaps

- Bootstrap and installation policy use operator authority. The setup and administration entry remains unresolved under [Q-01](prd.md#q-01) and [Q-10](prd.md#q-10); UI-001 only provides the sign-in handoff.
- Demo entry and reset have no dedicated screen ID. UF-025 and FR-058 trace reuse of the overview, monitors list, monitor details and incident details in the release demo. Validate the entry, lifecycle cues and reset affordance under [Q-13](prd.md#q-13).
- Maintenance-window effects on availability and latency have no validated rule or acceptance case. [Q-15](prd.md#q-15) tracks the gap for [FR-054](srs.md#fr-054) and [UF-024](user-flows.md#uf-024). [FR-064](srs.md#fr-064) covers MVP single-monitor conventions.
- Operational background, CI, measurement and policy verification rows can omit a user story or product screen when the actor is the platform or reviewer and the evidence is operational. Technical diagnostics and Grafana use operating surfaces outside the UI catalog. Business-rule links apply where product policy governs the requirement. Workflow-independent controls use their acceptance cases.
- Open requirement dependencies include notification provider configuration, approved fixtures, the reference workload and coverage scope, role details, history boundary behavior and browser support. See the [open question register](prd.md#open-questions) for the full owner-validation agenda. Missing product parameters keep affected acceptance cases conditional.
